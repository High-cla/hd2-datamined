# Mod 合并器：让多个改同一份文件不同字段的 mod 共存（build `26088801`）

> **问题**：每个 mod 都整份替换 `generated_entities.dl_bin`（47 MB）。两个 mod 装同一份文件时，
> 后装的覆盖先装的 —— 而它们的改动**其实互不冲突**，只是没人做并集。
>
> **解法**：把 mod 的语义抽出来（稀疏字节改写），取并集、逐字节判冲突、重新解**一个**校正字。

## 0. 一句话原理

一个守规矩的 mod 相对原版只有两类差异：

```
真实改动   —— 用户想要的那些字节
哈希脚手架 —— ① 末块 payload 尺寸字段（长度变了要同步）② 末尾追加区里的校正字
```

把脚手架剔掉，剩下的就是**可以直接做集合运算的语义**。合并后重新做一次 tail 宿主、重新解一个校正字即可。

## 1. 算法（`tools/dlbin_merge.py`）

1. **以原版明文为基底**（明文或封包都行，封包给 `--key` 解封）
2. **校验每个 mod 的明文 MurmurHash64A == 原版值**
   —— 这是「守规矩的保哈希 mod」的**强证据**。不相等 ⇒ 它改过长度或换了哈希 ⇒ **直接拒绝，不猜**
3. 逐字节 diff，得到该 mod 的改动集合
4. **剔除脚手架**：末块 payload 尺寸字段（4 B）+ 原版长度之后的整个追加区
5. 取并集；**逐字节**判冲突（同一偏移被写成不同值）
6. 重新 tail 宿主 → 解**一个**校正字 → 5 道门禁

## 2. 用法

```bash
# 先看报告（不写文件）
python tools/dlbin_merge.py --vanilla <原版明文> \
    --mod modA.dl_bin --mod modB.dl_bin --key <recipient.sk> --report-only

# 合并 + 封装
python tools/dlbin_merge.py --vanilla <原版明文> \
    --mod modA.dl_bin --mod modB.dl_bin --key <recipient.sk> \
    --out merged.plain --seal --pk <recipient.pk>
```

输入可以是明文（`*_entities.plain`）或封包，自动识别。冲突默认**中止**；
确实要「后来的覆盖」加 `--on-conflict after`（报告里会列出被覆盖的字节）。

## 3. 验证（本 build 实测）

把「四把背包武器自带备弹」拆成**四个独立 mod**（每个只改一把武器 + 它那条 rack），再合并：

| 输入 | 真实改动 | 脚手架（已剔除） |
|---|---:|---:|
| `mod_gr8` | 3 B / 3 段 | 1 B |
| `mod_spear` | 3 B / 3 段 | 1 B |
| `mod_rl77` | 3 B / 3 段 | 1 B |
| `mod_wasp` | 3 B / 3 段 | 1 B |

合并结果 12 B 改动，门禁 5/5 通过，且：

```
合并产物   sha256 cd91fcbe4c69e0df
上机验证件 sha256 cd91fcbe4c69e0df   （四把一次改完、实机四把全绿的版本）
逐字节相同 = True
```

⇒ **合并器不只是"看起来对"，它与「一次性改完」在字节层面不可区分。**

冲突检测也验过：把 GR-8 的 `+0x94` 一个写成 5、一个写成 9，合并直接中止并打印

```
0x008EA40: mod_gr8.plain=0x05  vs  mod_conflict.plain=0x09
```

## 4. 前提与边界

| 项 | 说明 |
|---|---|
| **必须都是保哈希 mod** | 明文 Murmur 必须等于原版值；否则拒绝（这条同时挡掉了"改了长度却没重解哈希"的坏 mod） |
| 容器形状 | 只认本仓库这两种：实体库（28 B 块头块序列）与设置表（`u32 组数` + 24 B 块头） |
| 脚手架识别 | 依赖 **tail 宿主**。若某个 mod 把校正字藏在行内空垫，那 8 B 会被当成"真实改动"——**冲突检测会抓住它**，属于保守失败，不会静默写坏 |
| 不处理 | 修改**文件名/资源**的 mod（那是包层，不是数据层）；也不处理把整行搬来搬去的语义冲突（字节层面能合并，语义是否合理要人判） |
| 冲突语义 | 逐字节判。两个 mod 改同一 u32 的不同字节（如两个独立 u8 开关）**不算冲突**，能正确合并 |

## 5. 与工具链的关系

```
entity_batch_set.py / entity_field_set.py   → 产出「改了点字段」的明文
dlbin_seal.py                               → 封装成 .dl_bin
dlbin_merge.py                              → 多个 .dl_bin 取并集    ← 本文
dlbin_deploy.py                             → 安装 / 回滚
```

发布侧建议：**每个 mod 只改自己那份字段**，用户想全装就用合并器一次性合成，
而不是让用户去挑"哪一个 mod 优先级更高"。
