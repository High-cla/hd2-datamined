# 新路线选择：战备线 vs 护甲线（build 26088801）

两条候选都是"改数据表 → 封包 → 写回"这条既有的离线路线，不带内存/Lua。判据只有四条：
**字段清不清、哈希闸门有没有落脚点、文件多大、验证要多久**。结论：**先开战备线**。

| 判据 | 战备线 `stratagem_settings` | 护甲线 `customization_armor_sets` |
|---|---|---|
| 表规模 | 153 行 × 400 B，明文 82,384 B，12 组 | 422 组（单记录），64 B 记录 + 变长尾（最大 4,408 B） |
| 想改的字段 | **全有**：`+80` uses、`+84` call-in(f32)、`+104` cooldown(f32)、`+392` 面板格 | **没有数值**（rating/speed/stamina 都不在这张表里） |
| 字段证据强度 | wiki 冷却 34/35 一致 + 1.007.200 补丁说明解释掉 Airburst 90/100 + cone 35→27 对上补丁 | 只有名字/描述三个 locid 槽（`+12/+16/+20`）是硬的 |
| 哈希闸门落脚点 | 行内 13 段空隙（最长 7 B）不够 8 B，但**有两个 `(NOT USED)` 战备行**可当宿主 | 该类型 **0 段空隙**；422 行里没有已证实的孤儿行 |
| 封包 | 任意长度（recipient.pk，实测 82,432 B 往返一致） | 同（不是瓶颈） |
| 验证成本 | **战备面板直接看冷却数字**，不用进任务 | 要进装甲界面/挨打才看得出数值变化 |
| 阻塞项 | 无 | 得先做一轮"护甲数值在哪张表/哪个实体组件"的定位 |

## 战备线：写回路径已经跑通（离线，7 门禁全过）

`tools/stratagem_tune.py`，第一个实验 = **Orbital 380mm HE Barrage 冷却 240 → 60**：

```
明文 82,384 B  组 12  行 153
目标：组6 行6 type=0x80 'ORBITAL. 380MM HE BARRAGE'
宿主：组2 行10 'EAGLE. (NOT USED) AIR-TO-AIR MISSLES'  校正字 @ 12432
原始哈希 0x04BBE33EF809862A
  cooldown +104: 240.0 -> 60.0
  PASS  G1 长度不变
  PASS  G2 差异 ⊆ 目标行 ∪ 校正字        diff=9
  PASS  G3 重算哈希 == 原始哈希
  PASS  G4 目标字段读回
  PASS  G5 宿主行除校正字外未变
  PASS  G6 目标行其余字段未变
  PASS  G7 身份字段未变（+0 type、+40/44/48/52/56 本地化 ID）
✓ 全部门禁通过 -> out/stratagem_380mm_cd60.plain.dl_bin
```

封包与回读：

```
tools/dlbin_seal.py seal-key <plain> --key refs/dlbin/keys/recipient.pk --out out/...dl_bin
  -> 82,432 B（= 82,384 + 48 封装头）
open-key 解回来与明文逐字节一致 ✓
```

**宿主行的合法性**：`(NOT USED)` 这两行（type `0x24` / `0x96`）cell 都是 7（与真实鹰式战备共用格子）、
它们的显示名本地化 ID 是死引用（语料里不存在）、内部名自带 `(NOT USED)`。改的是它们行内的 8 个字节，
不碰任何字段语义 —— 如果实机发现面板把它渲染出来（不应发生），就把宿主换到另一行。

## 护甲线为什么先放一放（不是不做）

1. `customization_armor_sets` 的 64 B 记录里，16 个 4 字节槽扫完**没有**像样的数值字段：
   `+28` 只有 33 个离散小值（297/422 行为 0）、`+44` 是常量 `-1.0f`、`+48` 是 64（记录长度自描述）。
   `+32/+36` 是成对的大整数（像 hash）。
2. 组的尾部有 136~4,408 B 的**结构化嵌套数组**（40 B 一条、带 hash 与 `0xFFFFFFFF` 标记），
   护甲数值大概率在那一层或实体侧的护甲套件表（47 MB、另有哈希闸门）。
3. 该元素类型 `free_runs = 0`，行内没有放置校正字的空隙；要用宿主行得先证明某一行确实未使用。

所以护甲线要先做的是**字段定位**（不是写回），而战备线的字段定位已经做完了。
