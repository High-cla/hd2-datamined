# 武器弹药模型：三种供弹方式与「自带备弹」（build `26088801`）

> **一句话**：「背包装填」不是一条独立开关，而是**弹药挂在背包组件上 + 武器自己的备弹 = 0** 共同造成的。
> 把武器行的 `+0x50/+0x54/+0x58` 填上，它就能像别的武器一样自带备弹。

## 0. 验证状态

| 结论 | 状态 | 证据 |
|---|---|---|
| `WeaponRoundsComponentData`（`0x66081072`）= 25 行 × 136 B，键 = 武器实体键 | **✓ 离线** | 哈希图 25 键；行号由哈希图 → 行基址现算 |
| 行内 `+0x48` = 每匣弹数（f32） | **✓ 离线** | 全表与 wiki 弹匣容量一致（AC-8=10、Punisher=8、Veto=12） |
| **`+0x50` = 备弹上限** | **✓✓ 实机** | AC-8 写 0→40 后 HUD **出现备弹**且**能装填**（2026-10-23） |
| **`+0x58` = 初始备弹** | **✓✓ 实机** | 写 0→40 后 HUD 由 **0/40** 变 **40/40** |
| AC-8 原版备弹 = 0，是全表唯一 | **✓ 离线** | 其余 24 行备弹在 20–100 之间 |
| 背包弹药在 **`0xC435BA85`**（背包实体上的组件），`+0` 每匣弹数 / `+8` 匣数 | **✓ 离线** | Autocannon Backpack = `10 / −1 / 5` ⇒ 10×5 = 50 发，与实机一致 |
| AC-8 换成「自带备弹」后，舱里只出武器、不需要背包 | **✓✓ 实机** | rack `spawn` 2→1 + 三个备弹字段（2026-10-23） |
| `+0x54`（备弹 B）语义 | **⚠ 未证** | 本 build 全表与 `+0x50` 同值或同比例，按镜像填即可 |
| `+0x5C` / `+0x60` 语义 | **⚠ 未证** | AC-8=`5`/`6.0`，Veto=`6`/`7.0`，其余均为 `1`/`0.0`；疑似「外部供弹匣数 / 每次耗时」 |

## 1. 三种供弹模型（按组件组合区分）

一件武器用哪种，看它挂了哪些组件：

| 模型 | 组件 | 例子 | 备弹在哪 |
|---|---|---|---|
| **弹匣式** | `WeaponMagazineComponentData`（`0xFB8D88A3`） | MG-43 | 武器行内 |
| **单发式** | `WeaponRoundsComponentData`（`0x66081072`） | AC-8、Punisher、Senator、Veto、Sweeper… | 武器行内 `+0x50` |
| **背包供弹** | `WeaponRounds` + 背包上的 `0xC435BA85` | AC-8 / GR-8 / Spear / RL-77 / W.A.S.P. | **背包**（武器自身写 0） |

注意 AC-8 同时属于第二、第三类：它的弹道/弹药走 `WeaponRounds`，但弹药实体挂在背包上。

## 2. `WeaponRoundsComponentData` 行字段（136 B）

| 偏移 | 类型 | 含义 | 判据 |
|---|---|---|---|
| `+0x40` | u32 | 主弹丸 id | AC-8 = 117 |
| `+0x44` | u32 | 备选弹丸 id | 双池武器非 0（Halt = 195） |
| `+0x48` | f32 | **每匣弹数** | 与 wiki 弹匣容量逐一对上 |
| `+0x4C` | f32 | 备选池每匣弹数 | 0 = 无 B 池 |
| **`+0x50`** | u32 | **备弹上限** | 实机（AC-8 0→40 生效） |
| **`+0x54`** | u32 | 备弹上限（B 镜像） | 与 `+0x50` 同值 |
| **`+0x58`** | u32 | **初始备弹** | 实机（0→40 后 40/40） |
| `+0x5C` | u32 | 未解（AC-8=5 / Veto=6 / 其余=1） | ⚠ |
| `+0x60` | f32 | 未解（AC-8=6.0 / Veto=7.0 / 其余=0.0） | ⚠ |

全表 25 行的 `备弹上限 / 初始` 对照（节选）：

| 武器 | 弹匣 | 备弹 | 初始 |
|---|---:|---:|---:|
| **Autocannon** | 10 | **0** | **0** |
| Punisher | 8 | 60 | 32 |
| Halt | 8 | 60 | 32 |
| Sweeper | 7 | 70 | 46 |
| Constitution | 5 | 100 | 60 |
| Veto | 12 | 90 | 52 |
| Senator | 6 | 40 | 32 |

⇒ **AC-8 是这一列唯一的 0**，这既是它「没背包就没弹」的原因，也是改动的落点。

## 3. 背包弹药组件 `0xC435BA85`（30 键 × 152 B）

| 偏移 | 含义 | Autocannon Backpack | Recoilless Rifle Backpack | Maxigun Backpack |
|---|---|---|---|---|
| `+0` | 每匣弹数 | 10 | 5 | 1000 |
| `+4` | 哨兵（多为 −1） | −1 | −1 | 1000 |
| `+8` | **匣数** | **5** | 3 | 500 |

⇒ AC-8 原版总计 = 10 × 5 = **50 发**，与实机一致。

## 4. 操作步骤

```bash
# ① 给武器填备弹（三格一起填）
python tools/entity_field_set.py set --block 0x66081072 --key <武器实体键> \
    --field 0x50 --type u32 --value 40 --expect-old 0 --out s1.plain
# 0x54、0x58 同理，把上一次输出当 --plain 链式再跑（哈希已保住，可安全链式）

# ② 让舱里只出武器（不要背包）
python tools/entity_field_set.py set --block 0xA98BB156 --key <rack 键> \
    --field 0x22C --type u32 --value 1 --expect-old 2 --out entities.plain

# ③ 封装 + 部署
python tools/dlbin_seal.py seal-key entities.plain --key <recipient.pk> --out generated_entities.dl_bin
python tools/dlbin_deploy.py install --file generated_entities.dl_bin --sealed generated_entities.dl_bin
```

本 build 实测值（AC-8）：`--block 0x66081072 --key 0xA8CFFB316F0B5C5F`，行 23 @`0x5A7DC4`；
rack 4 键 `0x5F41C4DCABE95421`，`+556` = 绝对 `0x22C`。

门禁：`entity_field_set.py` 7 道（G1/G2/G3/G4/G6/G7/G8），要求重算 Murmur == 原值
（本 build 实体库 `8E49771B181FFAA1`）。链式调用时每一步都会重新验一次。

## 5. 坑：清空槽位 ≠ 少生成一件

第一次尝试是「把 rack 4 的槽 2（背包）改成空」，结果**舱里出现两把 AC-8** ——
因为引擎跳过了空槽，把后面 authored 的槽 3（也是一把 AC-8）顶上来了。

**正解是改生成数量 `+556`（rack 行内 `+0x22C`）**，槽位数据一个字都不用动。
详见 [POD-RACK §2](POD-RACK-26088801.md)。

## 6. 边界与未解

- 本方法只改「有没有自己的备弹」，**不改**弹药挂在哪：背包供弹武器的 `0xC435BA85` 仍然在背包上，
  所以**换掉它的背包仍然会失去那部分弹药**（[实测](../engine/LIMITED-CROSS-PACKAGE-LOADING-26088801.md)：
  AC-8 背包换成 B-1 后完全无法装填）。
- `WeaponRounds` 与 `WeaponMagazine` 两套模型**不能互换**：新增一种弹药模型的行属于
  「给武器新增行」那条已否证/未解的路（见 [ENTITY-TABLE §9.7](ENTITY-TABLE-25988413.md)）。
- `+0x54` / `+0x5C` / `+0x60` 语义未证；本 build 只验证了 `+0x50` 与 `+0x58` 的实际效果。
- 只测了 AC-8 一把。**别的背包供弹武器（GR-8 / Spear / RL-77 / W.A.S.P.）是否同样只需填三个字段，未测。**
