# 10x Scope × ApexScope 准星贴图替换（2026-10-21）

第三方资源 mod 的"换贴图"委托第一次落地。目标：把 ApexScope 的十字准星画进 `10x Scope v1`
的准星槽位，其余资源不动。

## 1. 两个 mod 的贴图清单与角色判定

两个补丁都是 `9ba626afa44a3aa3.patch_N` + `.gpu_resources` 结构，贴图像素在伴生文件里，
patch 内的 `texture` 条目只有 340 字节头（15 项 mip 表 + 148 字节 DDS 头）。

10x Scope（4 张）：

| file_id | 尺寸 | mip | 真实 DXGI | 判定 |
|---|---:|---:|---|---|
| `8CECE9664922DAED` | 1024² | 11 | 71 = **BC1_UNORM** | 准星遮罩（黑底白线）|
| `43FE415553FC2CD5` | 1024² | 11 | BC7 | 镜片渐晕（淡紫径向渐变）|
| `CAD1793400495387` | 512² | 10 | B5G6R5 | 镜片圆形遮罩（LensOcclusionSize=0.38）|
| `0DCA3580DC95FFF2` | 1² | 1 | R8G8B8A8 | 占位 |

判定依据不是猜的，是材质 JSON 里的着色器变量：

```
ReticleColor          (0, 1, 0)   绿
ReticleColorIntensity 12.0
ReticleOpacity        0.22
ReticuleScale         0.16
LensEmissiveIntensity 1.0
LensOcclusionSize     0.38
LensColor             (0,0,0)
LensOpacityMul        0.4
```

放大 12 倍 × 0.22 不透明度的加色通道只可能是准星；镜片才是 `Lens*` 那一组。所以
`8CEC` 是准星槽位，语义是 **亮度 = 准星亮度（黑 = 不发光）**。

ApexScope（14 张，本次只用到 `A9244F893EA6055B`，1024²，DXGI 80 = B5G6R5，
但载荷 699,064 字节 = BC1 的 11 级 mip 尺寸，即**头写 16 位、数据是 BC1 足迹**，
作者工具留下的不一致；不影响读取，Pillow 按 DXGI 80 打不开，只能按图像使用）。

## 2. 极性相反，为什么不能直接反相

两张图是互补的：

- 10x `8CEC`：黑底 + 白准星（亮度 = 准星）
- Apex `A9244F`：**白镜头盘 + 黑准星**（对比度 = 准星，亮度是镜片）

用户直读：`srgb=0, 1024×1024`，alpha 全 255，256 级灰度。实测结构：

| 采样 | 值 |
|---|---|
| 四角 | 0 |
| 圆心 (512,512) | 0（准星线压在上面）|
| 竖列 x=512 | y=0..64 → 0，y=160..480 → 255 |
| 横排 y=512 | 全 0（横线贯穿整幅）|
| 圆盘 bbox (A>64) | (88,90)-(934,936)，中心 (511.5, 513) |
| 径向亮度 | r≤340 全 255；340→475 平滑降到 0 |

直接 `255 - A` 会把**镜头外的黑底翻成整片白**（准星 quad 在 0.16 缩放下就是一块白方块），
而且镜头边缘那道宽 ~135 px 的渐变会变成一圈灰白环。

正确的提取式是"反相后的**顶帽**"：

```
top-hat(v) = max_local(A) - A          # 结构元 9×9，大于最粗笔画(4~5 px)
```

逐点看这个式子等于什么：

| 位置 | max_local(A) | 结果 |
|---|---|---|
| 笔画像素（A=0，四周是亮镜片）| 255 | 255 白线 |
| 镜片内部/镜头外（均匀区）| = A | 0 |
| 镜头渐变（单调斜坡）| ≈ A（开运算沿斜坡平移回去）| ≈ 0 |
| 镜头外、远离笔画 | 0 | 0 |

顺带得到一个好性质：笔画的**幅度跟着局部镜片亮度走**，所以准星在镜片边缘自然衰减，
不需要再套一个硬圆形遮罩去切。这就是 `tools/lensmask_to_reticle.py` 的做法。

结果：27,339 个非零像素（2.61%），其中 3,761 px 达到 224~255，与 10x 原准星
（纯白线条、黑底）同一形态。

## 3. 工具链（两个新工具）

`tools/lensmask_to_reticle.py`：镜头图 → 准星遮罩（反相 + 结构元可调 + 可选黑场）。

`tools/swap_texture.py`：`<patch> --id <FILEID> --image <png> -o <out> --name <patch_N>`，
流程与硬性约束：

1. `srkit unpack` 整包到临时工作区（不只是 texture，pack 需要全量资源）
2. 原 DDS 的**前 148 字节头原样保留**——格式/尺寸/mip 数/标志全部不动
3. 逐级 mip：`BOX` 重采样（线性格式，代码值域平均即物理正确）→ Pillow DXT1/DXT5 编码块
4. **像素 blob 长度必须与原来逐字节相等**（699,064），否则拒绝打包（保 TOC 偏移）
5. `srkit pack --name` 生成新补丁 + 伴生
6. 验证：重新解包新补丁，逐个条目比对 `sha256`——除目标纹理的 `gpu` 外必须全部一致

## 5. 顺带修掉的工具 bug

`tools/export_textures.py` 里的 DXGI 表整体错位一格（缺 TYPELESS 项），
把 71 标成 `BC1_UNORM_SRGB`、80 标成 `B5G6R5_UNORM` 等。`srkit` 自己的表是对的
（`srkit/resources/texture.py`，71 = BC1_UNORM）。已按 DXGI 规范重写该表；
**已导出的文件名保持原样**（用户已引用），重跑导出才会换成正确名字。

> ⚠ 结论修正：`refs/scopes/10x_scope/INDEX.md` 里 `8CECE9664922DAED` 标的是
> `BC1_UNORM_SRGB`，实际是 `BC1_UNORM`（DXGI 71）。本 build 的准星贴图不带 sRGB 转换。
