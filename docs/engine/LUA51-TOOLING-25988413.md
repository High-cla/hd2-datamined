# Lua 5.1 tooling after build 25988413

Written 2026-10-20 while porting this project's instrumentation from a LuaJIT host to the stock Lua 5.1
that build 25988413 runs.

## 1. What the game's own DLL told us, by disappearing

Until this build, `bin/lua51.dll` shipped with the game and `tools/lua51_check.py` loaded it with
`ctypes` and called `luaL_loadbuffer` - gate "LUA51" in `docs/DISCIPLINES.md` §9, used by
`g1-vehicle-flight/probe/build_vfaplocate_kit.py` before every package.

| | 25480438 | 25988413 |
|---|---|---|
| `bin/lua51.dll` | 469,080 B, contains `Lua 5.1` **and `LuaJIT 2`** | **absent** |
| VM | LuaJIT, in that DLL | stock Lua 5.1.4, statically linked into `helldivers2.exe` |

So the gate had been quietly validating payloads against **LuaJIT**, and after the update it had no DLL
left to load at all - it returned exit 2 ("missing; cannot check"), which is fail-closed but blocks every
build. That is now fixed (below), and the fix had to answer the same question the DLL used to answer:
where does a real Lua 5.1 come from on a machine with no C compiler?

## 2. Where the 5.1 comes from now

`pip install lupa` - the wheel bundles real Lua builds as extension modules
(`lupa/lua51 … lua55`, plus `luajit20`/`luajit21`). `lupa.lua51` reports `_VERSION == "Lua 5.1"` and
behaves like stock 5.1. No compiler, no system install, no DLL to go missing:

```
python tools/lua51_check.py --selftest
  parser: lupa.lua51 - stock Lua Lua 5.1 (lupa.lua51)
  PASS plain Lua 5.1 / PASS hex escape refused / PASS // refused / PASS bitop refused / PASS goto refused
  PASS string.dump magic b'\x1bLua'
  PASS luac51_disasm consumes a real-5.1 chunk exactly
```

`tools/lua51_check.py` still prefers the game's own DLL **if a future build ships one again**, but it
refuses a DLL that contains the string `LuaJIT` - validating against LuaJIT is the exact mistake that
tool exists to prevent.

## 3. The finding that matters: `\x` does not fail, it silently changes the string

Stock Lua 5.1's lexer treats an unknown escape by **dropping the backslash and keeping the character**.
LuaJIT treats `"\x41"` as the byte `A`. Measured, not recalled:

```
local a = "\x41"     -> a == "x41"     (stock 5.1)
                        a == "A"       (LuaJIT)
return "\65"         -> "A"            (decimal escapes are real in both)
```

This is worse than a syntax error: the payload **compiles and loads** in the game and then produces
different bytes. No compiler check can see it, so `tools/lua51_check.py --lint` now greps for it (and for
`bit.` / `jit.` / `ffi.` / `table.new` / `table.clear` / `string.buffer`, which are simply `nil` there).

**Blast radius in this repo** (462 `.lua` files scanned, `tmp/scan_luajit_only.py`):

| construct | occurrences | files |
|---|---|---|
| `ffi.` | 2,068 | 110 |
| `\x` hex escape | **1,675** | **18** |
| `bit.` | 209 | 46 |
| `jit.` | 130 | 42 |

The 18 hex-escape files include `g2-vehicle-loadout/probe/mount_recon.lua` (245 occurrences) and three
shipped `b2x` payloads (4 each). None of them can run today anyway (no loader), but any future port must
convert `\xNN` to `\NNN` decimal escapes, or its strings will quietly differ.

## 4. `--dump` caveat: our chunks are not the game's chunks

`string.dump` on a 64-bit Lua produces a header with `sizeof(size_t) = 8`. **The game's own chunks say
`4`** (a 32-bit-width header, measured across every lua resource in the build). Whether the game's loader
checks that field is unproven, so shipping locally dumped bytecode is a gamble; **source payloads are
proven to load** (boot probe, §5 of `docs/BUILD-25988413.md`) and remain the recommended form.

`tools/luac51_disasm.py` now accepts both widths and says which one it read - it previously hardcoded
`(4,4,4,8)` and rejected every chunk produced locally, which is how this was found.

## 5. Tooling inventory after today

| tool | role | self-proof |
|---|---|---|
| `tools/lua51_check.py` | parse a payload with real Lua 5.1; `--lint` for LuaJIT-only constructs; `--dump` to emit a 5.1 chunk | `--selftest`, 7 checks, and it cross-checks with the disassembler |
| `tools/luac51_disasm.py` | disassemble a Lua 5.1 chunk (32- and 64-bit `size_t`) | `--selftest`, 6 checks, must consume the chunk exactly |
| `boot-probe/build_boot_probe.py` gate 2b | refuses to package a payload stock 5.1 rejects or lints | mutation-tested: a `//` payload and a `\x` payload are both refused |
| `tmp/scan_luajit_only.py` | corpus-wide blast radius of LuaJIT-only constructs | counts only; no verdicts |

What we still do **not** have: an official `luac -l`. `lupa` + the disassembler covers disassembly, and
`luac`'s listing format is not needed for anything here.
